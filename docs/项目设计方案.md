## 命名方案

| 用途 | 名称 |
|---|---|
| 工程名/仓库名 | `retraNote` |
| 展示名 | `RetraNote` |
| 中文简称 | **溯笺** |
| Python 包名 | `retra_note` |
| 项目全称 | **RetraNote 公开课程视频可追溯知识卡与片段定位助手** |
| API 文档标题 | `RetraNote API` |

### 命名逻辑

- **溯**：追溯时间戳、原文片段、引用来源，对应项目核心“可追溯”。
- **笺**：知识卡、笔记、复习材料，对应“知识卡”。
- **RetraNote**：`Retrace`（追溯）+ `Note`（笔记/知识卡）的造词，不是“溯笺”的直译。
- 它不属于“飞河 / Fly River”那种自然意象直译风格，而是**概念造词 + 中文文雅简称**。
- `retraNote` 适合小驼峰工程名；`retra_note` 适合 Python 包名；`RetraNote` 
  适合 README、演示视频、API 标题。

### 项目中描述

```text
项目工程名：retraNote
产品展示名：RetraNote
中文简称：溯笺
项目全称：RetraNote 公开课程视频可追溯知识卡与片段定位助手
仓库描述：将公开课程视频字幕转化为带时间戳引用的知识卡、复习题与片段定位结果。
```

> **工程名 `retraNote`，中文简称“溯笺”，艺术化英文名 `RetraNote`。**

理由：它同时覆盖“追溯”和“知识卡”，中文简称有辨识度，英文名是造词而非直译，
适合作为 GitHub 仓库、API 标题、PRD 封面和演示视频统一品牌。后续文档、
README、Docker 服务名、API 标题都可以统一用这一组，不再混用“视频总结
助手”这类直白名作为品牌名；直白描述只放在副标题里。

## 附录：v0 vs v1 逐项对比

### A. v1 不当作新增能力、但会继承的能力（v0 文档已规划）

链接解析（BV/av/短链/分P）、WBI 签名、SESSDATA 配置、无字幕转写规划、后台任务与轮询、记录管理/搜索/导出、时间戳跳转、错误处理表、模型可配置、封面本地缓存、SQLite + SQLModel。

**处理方式**：v1 照做，但叙事上定位为“继承 v0 已验证的交互”，不列为差异化。

### B. v1 真正的差异化（v0 没有，或只有规划没有验证）

| 能力 | v0 | v1 |
|---|---|---|
| 分块目的 | 防 token 超限，切片后分段调用合并 | 建索引，支持 TopK 检索与片段定位 |
| 检索 | 无向量库、无检索接口 | Chroma 向量入库 + TopK 检索 + 片段定位 API |
| 引用校验 | 时间戳范围校验 + 就近校正 | quote 是否在原文、时间戳是否对齐、结论是否超出证据、证据强度 |
| 评估 | 无 | 20—30 条评估集 + 一键跑分 + badcase 分类与复现 |
| 测试 | 未提 | pytest 覆盖解析、检索、引用校验、API |
| 作者可解释性 | 文档 AI 写，代码未读，无法验证 | 契约先行、核心模块自己写、AI 代码配测试、按用户故事提交 |
| 部署 | PyInstaller exe，双击即用 | Dockerfile + docker compose 一键启动，强调可复现 |
| 文档 | AI 生成，未与实现校验 | 作者主导判断，决策记录可追溯 |

### C. 定位差异

| 维度 | v0 | v1 |
|---|---|---|
| 产品形态 | 自用优先的本地网页工具，exe 分发给普通用户 | 可评估 RAG 后端服务，面向面试展示与复现 |
| 前端 | Jinja2 + Tailwind，产品级界面 | Streamlit 单页，仅作 API 演示壳 |
| 部署 | exe 双击即用 | docker compose 一键启动 |
| 目标 | 自用效率工具 | 工程能力与产品思维的作品集 |

### D. 面试预备问答

**问**：你 v0 技术架构文档里写了 WBI 签名、时间戳校正、字幕切片，为什么 v1 还做？

**答**：v0 的文档是 AI 生成的，代码我没有读过，无法确认文档描述和实现是否一致，也无法测试和迭代。这是我说的黑箱：不是没有文档，而是文档和代码我都无法验证。v1 我不再依赖 AI 写了什么，而是从 API 契约开始自己设计，核心模块自己写，每个模块配测试，用评估集判断迭代是否有效。v0 的切片是为了防 token 超限，v1 的分块是为了建索引和检索定位，目的不同；v0 的时间戳校正只校验范围，v1 的引用校验要校验 quote 是否在原文、结论是否超出证据。

**问**：v1 的 Streamlit 还不如 v0 的网页，为什么退步？

**答**：v1 不是分发工具，是展示后端服务与评估闭环的作品。Streamlit 只是 API 演示壳，正式前端不在范围；v1 的重点是检索链路、引用校验、评估集和 Docker 可复现，不是 UI 完成度。
