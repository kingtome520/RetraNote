# RetraNote Product Brief

> 工程名：`retraNote` ｜ 展示名：RetraNote ｜ 中文简称：溯笺 ｜ Python 包名：`retra_note`

> 项目全称：RetraNote 公开课程视频可评估知识卡与片段定位助手

---

## 1. 一句话定位

**RetraNote（溯笺）** 是面向公开课程视频的“可评估知识卡与片段定位”后端服务。用户粘贴公开课程视频链接，系统导入字幕并生成带时间戳原文引用的章节知识卡、复习题和片段定位结果；每条结论可回溯、可校验，并通过评估集与 badcase 闭环持续度量效果。**它不是聊天机器人，也不是视频搜索推荐工具。**

## 2. 要解决的核心问题

- 长课程视频的 AI 总结通常是黑箱，用户无法定位“这句话在视频哪里说的”；
- 复习时想找某个知识点，只能拖进度条或重新看；
- 现有 AI 总结不可评估，用户不知道哪些结论可信、哪些是模型编的；
- 用户选定课程视频后，缺少把长视频转化为可复习、可定位知识卡的手段；本项目**不解决“选哪条视频”**，只解决“选定的视频如何变成可追溯、可校验的知识卡”；
- 旧项目 v0 能生成总结和时间戳历史记录，但文档由 AI 生成、代码未深入阅读，属于“有文档但无法验证”的黑箱：无法确认实现与文档是否一致，也没有评估集和 badcase 分析，无法判断迭代是否有效。

## 3. 目标用户假设（先假设，下一步画像验证）

- **主要**：备考/自学的大学生，观看 30 分钟以上公开课程视频；
- **次要**：转行自学者，需要把课程整理成复习材料；
- **非目标**：企业培训管理员、多人协作团队、需要批量课程管理的机构用户、需要视频推荐/搜索的用户。

## 4. 价值主张

> 不只是“帮你总结视频”，而是“每条结论都能回到视频时间戳和原文片段，结论是否超出证据可被校验，整体效果可被评估集度量”。

差异化不在功能列表，而在以下五件事。**v0 技术架构文档中已规划的 WBI 签名、时间窗口切片、时间戳范围校正、无字幕转写、后台任务、记录管理，均不计入 v1 新增能力**；v1 把它们视为“继承 v0 已验证的交互”，不当作卖点。

| 差异化能力 | v0 实际状态 | v1 要做的 |
|---|---|---|
| **RAG 检索链路** | 文档只写“按时间窗口切片、分段调用后合并”，目的是防 token 超限；无向量库、无 TopK 检索、无片段定位 | 分块建索引 + Chroma 向量入库 + TopK 检索 + 片段定位接口。分块目的是“可检索定位”，不是“塞进上下文” |
| **引用校验器** | 文档只写“时间戳不超过时长、按字幕段就近校正”，是时间范围校验 | 校验 quote 是否在原文片段、时间戳是否对齐、结论是否超出证据；输出证据强度（充分/不足/未找到原文） |
| **评估集 + badcase 闭环** | 完全没有 | 20—30 条评估集、一键跑分、badcase 分类与复现链接 |
| **pytest 测试** | 文档未提 | 覆盖解析、检索、引用校验、API 契约 |
| **作者能解释每一层** | 文档 AI 写，代码未读，无法确认实现与文档一致 | 契约先行、核心模块自己写、AI 代码必须配测试、按用户故事提交 Git、保留决策记录 |

**定位差异**（不是功能差异，但必须讲清）：v0 是自用优先的本地网页工具，用 Jinja2 + Tailwind 做产品界面、PyInstaller 打包 exe 分发给普通用户；v1 是可评估 RAG 后端服务，用 Streamlit 单页仅作 API 演示壳、Docker 一键启动、面向面试展示与复现。v1 不追求产品级 UI，不追求 exe 分发。

## 5. 与旧项目 v0 的关系

v0（helpSeeVideo）是自用优先的本地 B 站视频总结工具，已验证“链接导入 + 结构化总结 + 时间戳跳转 + 历史记录”的需求。但 v0 的文档由 AI 生成、代码我未深入阅读，属于“有文档但无法验证”的黑箱。**v1 RetraNote 采用独立新仓库，不复用 v0 代码**，而是重新设计为可评估 RAG 后端：补上 v0 没有的检索与片段定位、引用校验、评估集与 badcase 闭环，并用 pytest 和 Docker 保证可复现。v0 是需求验证原型，v1 是作者能解释每一层的工程作品。逐项对比见附录。

## 6. 成功指标（MVP 可测）

- 片段定位 Top3 命中率 ≥ 70%（20—30 条评估集）；
- 知识卡引用可追溯率 ≥ 90%：结论能在原文找到对应 quote；
- 时间戳对齐率：引用时间戳与片段起止时间一致；
- 知识卡人工可用率抽检 ≥ 3/5 分；
- 复习题可答率与答案一致性抽检达标；
- 导入成功率与失败分类覆盖率：失败必须给出明确原因，不能静默降级；
- 单视频导入到可检索 ≤ 3 分钟（演示规模，原生字幕场景）；
- badcase 有分类记录并可复现；
- 评估跑分脚本可一键复现报告；
- 核心模块（解析、检索、引用校验、API）有 pytest 覆盖。

## 7. 本版范围（MVP 做）

- 链接导入为主路径（B 站公开课程视频为主），封装为 `SubtitleResolver` 适配器；
- 字幕文件上传（SRT/VTT/TXT）作为兜底降级；
- 失败原因分类：无字幕轨、登录态缺失/过期、风控、网络超时、视频不可用、解析失败；
- 字幕标准化为 `segment_id / start / end / text / source / language`；
- 分块、向量入库（Chroma）、TopK 检索；
- 章节知识卡、复习题、片段定位；
- 引用校验器：quote 是否在原文、时间戳是否对齐、结论是否超出证据；
- 证据锚点与证据强度提示：证据充分/不足/未找到原文；
- 导入记录与知识卡版本快照：记录链接、平台、字幕来源、导入时间、参数版本、失败原因；
- badcase 记录接口：引用不准、分块断裂、检索错片段、生成超出原文、时间戳偏移；
- 20—30 条评估集与一键跑分脚本；
- FastAPI + Streamlit 单页演示壳 + pytest + 日志；
- Dockerfile + docker compose 一键启动；
- PRD、README、API 文档、演示视频脚本、v0 baseline 对比文档。

## 8. 明确不做（非范围）

- 不做自由聊天机器人；
- 不做批量抓取前 30/50 条视频入库；
- 不做视频搜索推荐工具；
- 不做知识库更新检测（放 roadmap，MVP 只保留导入记录与版本快照）；
- 不做复杂多用户权限；
- 不上 Celery/Redis/监控体系；
- 不做移动端/正式前端；
- 不做与 v0 同形态的 exe 分发工具；v1 用 Docker 展示可复现工程能力；
- 不绕过登录/权限，不承诺所有视频链接都能导入，失败降级到上传字幕；
- 不承诺无原生字幕视频的 ASR 转写（ASR 放 Phase 2）。

## 9. 约束与风险

- 单人开发，4—6 周 MVP，8—12 周完整版；
- B 站字幕依赖登录态和风控，可能失败 → 适配器 + 失败分类 + 文件兜底；
- 并非所有视频有原生字幕 → MVP 明确提示，ASR 放 Phase 2；
- yt-dlp/ffmpeg 是外部依赖，Docker 镜像会变大 → README 写清依赖；
- 前端联调弱 → Streamlit 单页壳，不做正式前端；
- AI 辅助编码可能黑箱 → 契约先行、核心模块自己写、AI 代码必须配测试、按用户故事提交 Git、保留决策记录；
- 预算：现有 API Key，控制调用量，评估集跑分记录 token 消耗。

## 10. 关键决策记录（ADR 雏形）

1. **链接导入做主路径，但封装为适配器，文件上传兜底。** 理由：延续旧项目体验 + 控制外部依赖风险。
2. **不做聊天机器人。** 理由：烂大街，且不利于展示可追溯与评估。
3. **不做批量抓取和视频搜索推荐。** 理由：范围爆炸、质量失控，且会偏离 RAG 与评估能力展示。
4. **历史记录保留为基础功能，知识库更新检测放 roadmap。** 理由：MVP 范围控制，但识别到知识库时效性是真实问题。
5. **SQLite 起步、Chroma 本地持久化。** 理由：单人 MVP 降低运维成本。
6. **异步任务用 BackgroundTasks + 任务表，不上队列；缓存作为 Phase 2。** 理由：4—6 周范围控制。
7. **差异化表述为“可校验 + 可评估 + 工程化 + 完整产品流程”，而不是只讲“可追溯”。** 理由：旧项目已具备基础可追溯能力，必须诚实面对并升级叙事。
8. **v1 采用独立新仓库，不复用 v0 代码。** 理由：v0 代码未读、无法验证，复用会延续黑箱；v1 从契约开始重新设计，确保可解释。
9. **v1 的 Streamlit 仅作演示壳，不做产品级前端。** 理由：v1 定位是后端服务与评估闭环展示，不是分发工具；产品前端不在范围。

## 11. 核心数据流

```text
视频链接 / 字幕文件
→ SubtitleResolver 适配器（B站API / yt-dlp / 文件上传）
→ 标准化字幕片段（保留 start/end）
→ 清洗与分块（保留时间戳）
→ 向量化入库（Chroma）
→ 用户输入知识点/关键词
→ TopK 检索片段
→ 结构化生成：知识卡 / 复习题 / 片段定位
→ 引用校验：quote 是否在原文、时间戳是否对齐、结论是否超出证据
→ 返回结果 + 证据锚点 + 证据强度
→ 用户标记 badcase
→ 评估集跑分与报告
```
