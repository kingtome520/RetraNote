# 决策日志（Decision Log）

本文件记录 RetraNote 项目过程中的关键决策。默认采用轻量记录：一条决策写清「决策、理由、影响范围」即可。
只有当决策**难改、纠结过、需要长期维护**时，才升级为正式 ADR，单独建档到 `docs/adr/ADR-xxx.md`。

升级 ADR 的触发条件（满足任一）：
- 决策一旦落地，后续推翻成本高（如数据存储、部署形态、核心接口契约）；
- 团队/评审中产生过分歧，需要留下取舍过程；
- 决策会影响第三方复用或长期维护（如对外 API、开源发布形态）。

当前已升级为 ADR 的决策：无。

## 一、范围控制类（轻量记录即可）

| 编号 | 决策 | 理由 | 影响范围 |
|---|---|---|---|
| D-001 | 不做聊天机器人 | 同类产品泛滥，且自由聊天不利于展示「可追溯引用 + 可评估」这两个差异化能力 | MVP 功能范围、演示脚本 |
| D-002 | 不做批量抓取和视频搜索推荐 | 不在 MVP 范围内；批量入库会带来范围爆炸与检索质量失控，搜索推荐会偏离 RAG 与评估能力展示 | MVP 功能范围、PRD 非范围章节 |
| D-003 | D 层只做任务表和简单缓存，不上 Celery/Redis/监控 | 4—6 周 MVP 范围控制，单人开发运维成本需压低 | 技术架构、部署形态 |
| D-004 | 历史记录保留为基础功能，知识库更新检测放 roadmap | 历史记录是 v0 已验证的交互，保留成本低；知识库时效性检测涉及版本对比与增量更新，超出 MVP | MVP 功能范围、roadmap |

## 二、技术选型类（部分候选升级 ADR）

| 编号 | 决策 | 理由 | 影响范围 | 升级 ADR？ |
|---|---|---|---|---|
| D-005 | 链接导入做主路径，但封装为 `SubtitleResolver` 适配器，字幕文件上传兜底 | 延续 v0 已验证的链接导入体验；同时把 B 站接口/风控/登录态的不确定性隔离在适配器内，失败可降级，不阻塞演示 | 数据入口设计、失败分类、演示策略 | **候选**：适配器契约一旦定型，后续新增平台（YouTube、ASR）都依赖它，建议第 2 周落地后补 ADR |
| D-006 | 存储用 SQLite + Chroma 本地持久化，起步不上独立数据库服务 | 单人 MVP 降低运维成本；SQLite 零配置，Chroma 本地持久化足够演示规模 | 数据层、部署形态 | **候选**：若后续换 PostgreSQL 或换向量库，迁移成本高，建议 MVP 跑通后补 ADR 记录取舍 |
| D-007 | 异步任务用 FastAPI BackgroundTasks + 任务表，不上消息队列 | 与 D-003 配套；演示规模下 BackgroundTasks 足够，任务表保证进度可查 | 任务模块、进度轮询 | 否（与 D-003 合并理解即可） |
| D-008 | 初始 LLM 服务选用 DeepSeek | ① OpenAI 兼容接口，切换成本低；② 单价低，评估集跑分与 badcase 复现的 token 成本可控；③ 中文总结质量满足课程字幕场景；④ v0 已使用同款模型，便于做 v0/v1 baseline 对比 | 生成模块、评估跑分、成本控制 | 否（可配置 base_url/model，切换成本低） |
